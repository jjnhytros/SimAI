## Stato del percorso 1.0

Il percorso `avvia → simula → interagisci → salva → ricarica` è
chiuso:

- `simai db upgrade` + `simai world seed` → avvio.
- `simai sim run --ticks N` → simulazione continua.
- `simai actions choose` / `simai sim tick` → interazione e ispezione.
- `simai save create` / `simai save list` / `simai save load` → salvataggio
  e ripresa.
- `simai save load` + `simai sim run` → continuazione.

## Incremento 0.13c — Soglie di bisogno al posto dei cooldown (COMPLETATO)

Il cooldown bloccante introdotto in 0.13b ha peggiorato le metriche:
mood medio in calo di 8–24 punti per NPC, log pieni di turni saltati.
La diagnosi era sbagliata: il problema non era "Erika mangia troppo",
era "Erika ha solo 2 azioni disponibili e non si sposta". Il cooldown
ha reso il problema cronico invece di attenuarlo.

- [x] Rimosso `ActionDef.cooldown_ticks` e `filter_by_cooldown`.
- [x] Rimosso `Need.last_satisfied_at_tick` (migrazione `0008`).
- [x] Aggiunto `ActionDef.max_need_to_start`: EAT 30, DRINK 40,
      PLAY 70, SOCIALIZE 70.
- [x] `filter_by_need_threshold(available, needs)` sostituisce il
      filtro per cooldown. Un'azione è disponibile solo se il bisogno
      che soddisfa è sotto la soglia.
- [x] `run_tick` e `do_action` usano la nuova logica. `do_action`
      distingue "non disponibile qui" da "non necessaria (bisogno già
      alto)".
- [x] `player status` mostra azioni disponibili e azioni "non
      necessarie".
- [x] Test `test_cooldown.py` rimosso, sostituito da `test_soglie.py`:
      soglie per design, filtro sotto/sopra soglia, NPC che mangia
      quando ha fame e salta quando è sazio, turno saltato quando tutti
      i bisogni sono alti.
- [x] `save`/`load` non serializzano più `last_satisfied_at_tick`:
      il payload è più semplice, il file .sav di 1.0.0 non contiene
      campi inutilizzati.

## Cosa resta come limite noto

Il problema strutturale "NPC immobili" resta in `known-issues.md` #1.
Un NPC in `casa` non può bere; un NPC in `piazza` non può mangiare.
Con le soglie il decadimento non porta più a fame/sete croniche nel
caso medio, ma la sete di Erika oscillerà comunque verso 0 nel lungo
periodo, perché non ha modo di bere dove vive.

Verrà risolto in 1.1 con movimento NPC (utility AI che considera
soddisfacibilità altrove).
