# Piano release 0.1160 — IntimacyService

**Data**: 2026-10-29
**Tipo**: feature comportamentale (tocca `run_tick` → 10y obbligatorio)
**Base**: 0.1150 (394 test verdi, `10y-0.1150.json`, tps 72.6)

## Motivazione

FASE 3.2c del TODO: `npc/intimacy/`. Oggi `Relationship.strength` è
un numero 0–100 letto solo da `boost_social_relationship` (SOCIALIZE
+5) e mostrato dalla CLI. Non ha livelli, non ha effetti sul mood.
L'IntimacyService dà profondità: `strength` → `intimacy_level` (0–5)
→ moodlet per livelli alti.

## Scope

1. `intimacy_level(strength) -> int` (pura).
2. `best_intimacy_level(session, char_id) -> int` (max su out+in).
3. `intimacy_levels_of(session, char_id) -> dict[str, int]` (CLI).
4. `apply_intimacy_moodlets(session, char_id, tick)`.
5. `MoodletKind`: +2 (`ROMANTIC`, `DEVOTED`).
6. `SPECS`: +2 entry.
7. `tick.py` fase 3: chiamata `apply_intimacy_moodlets` prima di
   `update_mood`.
8. CLI `relationships intimacy -c <key>`.
9. Test: `test_intimacy.py` (nuovo), `test_moodlets.py` (verifica
   `SPECS` completi).

## Non-scope

- Migrazione: `intimacy_level` è **derivato**, non persistito.
- `Relationship.intimacy_level` colonna: no.
- Boost SOCIALIZE scalato per livello: **no** (feedback loop →
  convergenza a 100 in pochi anni → tutti DEVOTED → moodlet inutile).
- `RelationshipKind.SPOUSE_OF`: esiste, ma il seed non lo crea. Se
  in futuro servirà, il moodlet `DEVOTED` copre già lo sposo.
- 60y: rimandato (deciso dopo 0.1150).

## Design

### Soglie `intimacy_level`

| strength | level |
| --- | --- |
| 0–19.99 | 0 |
| 20–39.99 | 1 |
| 40–59.99 | 2 |
| 60–79.99 | 3 |
| 80–94.99 | 4 |
| 95–100 | 5 |

### Moodlet

| level | kind | Δ/tick | duration |
| --- | --- | --- | --- |
| 4 | `ROMANTIC` | +0.5 | 2 |
| 5 | `DEVOTED` | +1.0 | 2 |

Durata 2 (non 1, non 28): piccola isteresi se lo stato oscilla tra
3 e 4. Rinfrescato ogni tick finché il livello è ≥ 4. Se scende a
≤ 3, scade in 2 tick.

`need=None` per questi moodlet (non need-based). `refresh_need_moodlets_many`
li ignora (filtra `need.isnot(None)`).

### `best_intimacy_level`

Max su relazioni **in uscita e in entrata**. Il seed è simmetrico,
quindi oggi equivalente a "out", ma la definizione "il mio miglior
legame, da qualunque parte" è più corretta. Se A↔B, il max è
invariato.

### `apply_intimacy_moodlets`

```python
level = best_intimacy_level(session, char_id)
if level >= 5:
    apply_moodlet(session, char_id, MoodletKind.DEVOTED, tick)
elif level >= 4:
    apply_moodlet(session, char_id, MoodletKind.ROMANTIC, tick)
