# SimAI 1.0 — Baseline

## Contesto

Il repository è stato inizializzato ex novo. Non esisteva codice precedente
riutilizzabile. Ogni componente della 1.0 verrà costruito rispettando il TODO
operativo `TODO_SimAI_1.0_Muse_Core.md` e la visione del TODO globale.

- [x] `pyproject.toml` con Python 3.13, hatchling, dipendenze core e dev.
- [x] Package `simai` con `__main__.py`, `__version__.py`, `py.typed`.
- [x] CLI Typer con `simai version`.
- [x] Configurazione Pydantic `Settings`.
- [x] Logging base con Loguru.
- [x] `.env.example`, `.gitignore`, `scripts/check.sh`.

- [x] `alembic.ini`, `alembic/env.py`, `script.py.mako`.
- [x] Migrazione `0001_initial` con tabella `core_version`.
- [x] Package `simai/db` con `Base`, `get_engine`, `get_session_factory`,
      `get_alembic_config`.
- [x] CLI `simai db upgrade / downgrade / status`.

## Cosa non è ancora incluso

- Nessun modello di dominio (NPC, world, needs, relationships).
- Nessun ciclo di simulazione, nessun tick.
- Nessuna UI.
- Nessun salvataggio `.sav`: solo il database SQLite.
- Nessun seed di Anthalys / Quartiere delle Muse.

## Prossimo incremento (0.5)

Utility AI deterministica minima: dato un personaggio con i suoi bisogni
correnti e un catalogo chiuso di azioni disponibili per location, produrre
una scelta riproducibile con seed. Nessun tempo, nessun movimento: solo la
decisione.

## Incremento 0.5 — Utility AI deterministica (COMPLETATO)

- [x] `ActionKind` (EAT, DRINK, PLAY, SOCIALIZE), `ActionDef` frozen,
      `CATALOG` chiuso con `allowed_at` per tipo di location.
- [x] `actions_for_location(kind)` filtra il catalogo per location corrente.
- [x] `score(action, needs)` = `(100 - value(action.satisfies)) * weight`.
- [x] `choose_action(needs, available, rng)` con jitter deterministico
      (`±JITTER`) e tie-break stabile su `kind.value`.
- [x] `rng_for_decision(master_seed, character_id)` con seed stringa
      `"simai:{seed}:{char_id}"` — indipendente da PYTHONHASHSEED.
- [x] CLI `simai actions choose --character <key> [--seed N]`.
- [x] Test: catalogo per location, scoring, urgenza dominante, determinismo
      (stesso seed → stessa scelta), varietà fra seed diversi, disponibilità
      vuota → None.

## Cosa non è ancora incluso (dopo 0.5)

- Nessuna esecuzione dell'azione: `choose` decide, non applica effetti.
- Nessun movimento fra location: se il bisogno urgente non è soddisfacibile
  dove il personaggio si trova, la decisione cade su un'altra azione
  disponibile (verrà gestito in 0.6 con il tick).
- Nessun concetto di tempo: il decadimento è ancora invocato esplicitamente.
- Nessuna relazione: `SOCIALIZE` soddisfa solo `INTIMACY` del personaggio
  agente.

## Prossimo incremento (0.6)

Tick minimo: `simai sim tick` applica decadimento per N minuti, poi per ogni
NPC sceglie un'azione con seed derivato dal tick, applica l'effetto sul
bisogno, registra la decisione. Nessuna animazione, nessuna UI, nessuna
persistenza del tick: solo il ciclo completo `decadimento → decisione → effetto`
con seed fisso.

## Prossimo incremento (0.6)

Tick minimo: `simai sim tick` applica decadimento per N minuti, poi per ogni
NPC sceglie un'azione con seed derivato dal tick, applica l'effetto sul
bisogno, registra la decisione. Nessuna animazione, nessuna UI: solo il ciclo
`decadimento → decisione → effetto` con seed fisso.

## Incremento 0.6 — Tick minimo (COMPLETATO)

- [x] `simai/sim/tick.py` con `run_tick(session, *, minutes, tick_index,
      master_seed, include_player=False)`.
- [x] Ciclo completo per NPC: `apply_decay → needs_of → choose_action →
      apply_effect`. Player escluso per default.
- [x] `TickDecision` e `TickReport` frozen: report tipizzato, non un dict.
- [x] `rng_for_decision(master_seed, character_id, tick=0)`: stessa
      decisione per stessa tripla.
- [x] `apply_effect(session, character_id, action)` clampato a 100.
- [x] CLI `simai sim tick -m MINUTES [--tick N] [--seed S] [--include-player]`.
- [x] Test: decisione per NPC, effetto non regressivo, determinismo
      cross-DB, esclusione player, errori su input non validi.

## Cosa non è ancora incluso (dopo 0.6)

- Il tick è stateless: l'indice è passato dall'utente, non persistito.
- Nessuna nozione di tempo di Anthalys: `minutes` è astratto, non
  convertito in ore/giorni.
- Nessuna persistenza delle decisioni: il report è solo output CLI.
- Nessun movimento fra location.
- Player controllabile: il tick lo esclude ma non c'è ancora un comando
  per fargli scegliere un'azione.

## Prossimo incremento (0.7)

Stato di simulazione persistente: tabella `sim_state` con `tick_index`
e `master_seed`, migrazione `0004`, seed idempotente, `simai sim tick`
legge e incrementa il contatore. `simai sim state` per vedere lo stato.
Questo è il prerequisito per il salvataggio: senza tick_index persistito,
"chiudere e riprendere" non ha senso.
