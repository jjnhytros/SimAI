# SimAI 1.0 — Baseline

## Contesto

Il repository è stato inizializzato ex novo. Non esisteva codice precedente
riutilizzabile. Ogni componente della 1.0 verrà costruito rispettando il TODO
operativo `TODO_SimAI_1.0_Muse_Core.md` e la visione del TODO globale.

## Incremento 0.1 — Baseline installabile (COMPLETATO)

- [x] `pyproject.toml` con Python 3.13, hatchling, dipendenze core e dev.
- [x] Package `simai` con `__main__.py`, `__version__.py`, `py.typed`.
- [x] CLI Typer con `simai version`.
- [x] Configurazione Pydantic `Settings`.
- [x] Logging base con Loguru.
- [x] `.env.example`, `.gitignore`, `scripts/check.sh`.
- [x] Test `test_cli_version`.

## Incremento 0.2 — DB, Alembic, `db upgrade` (COMPLETATO)

- [x] `alembic.ini`, `alembic/env.py`, `script.py.mako`.
- [x] Migrazione `0001_initial` con tabella `core_version`.
- [x] Package `simai/db` con `Base`, `get_engine`, `get_session_factory`,
      `get_alembic_config`.
- [x] CLI `simai db upgrade / downgrade / status`.
- [x] Test migrazioni: upgrade su vuoto, idempotenza, downgrade.
- [x] Smoke test CLI per `db upgrade` e `db status`.

## Cosa non è ancora incluso

- Nessun modello di dominio (NPC, world, needs, relationships).
- Nessun ciclo di simulazione, nessun tick.
- Nessuna UI.
- Nessun salvataggio `.sav`: solo il database SQLite.
- Nessun seed di Anthalys / Quartiere delle Muse.

## Prossimo incremento (0.3)

Seed minimo del mondo: entità `Location` e `Character` con migrazione
dedicata, `world seed` idempotente e test di idempotenza. Sarà la prima parte
del percorso verticale Muse Core.

## Incremento 0.3 — Entità di dominio e seed Muse Core (COMPLETATO)

- [x] Modelli `Location` e `Character` (SQLAlchemy 2.0, tipizzati).
- [x] Migrazione `0002_world_and_characters`.
- [x] `simai/db/registry.py` con `ensure_all_models_loaded()` richiamato da Alembic.
- [x] Seed idempotente del Quartiere delle Muse: 3 location, 5 personaggi
      (4 NPC + 1 Sim giocabile).
- [x] CLI `simai world seed` e `simai world list`.
- [x] Test: modelli, idempotenza del seed, smoke CLI.

## Cosa non è ancora incluso (dopo 0.3)

- Nessun bisogno, nessuna decisione, nessun tick.
- Nessuna relazione fra personaggi.
- Nessuna nozione di tempo di Anthalys.
- Nessun salvataggio `.sav` (solo DB).

## Prossimo incremento (0.4)

Bisogni essenziali (`HUNGER`, `THIRST`, `FUN`, `INTIMACY`) con migrazione
dedicata, valori iniziali nel seed e test di decadimento. Sarà la prima
meccanica realmente simulata del percorso Muse Core.

## Incremento 0.4 — Bisogni essenziali (COMPLETATO)

- [x] Modello `Need` con enum `NeedKind` (HUNGER, THIRST, FUN, INTIMACY).
- [x] Migrazione `0003_needs` con unique `(character_id, kind)`.
- [x] `simai/needs/service.py` con `clamp`, `decay_value`, `apply_decay`,
      `ensure_initial_needs`, `needs_of`.
- [x] Decadimento puro per ora simulata, senza tick: il tempo trascorso è
      passato esplicitamente al servizio.
- [x] Seed Muse Core popola 4 bisogni per ciascun personaggio (idempotente).
- [x] CLI `simai needs show` e `simai needs decay`.
- [x] Test: valori iniziali, idempotenza, decadimento proporzionale,
      floor a zero, no-op su minuti non positivi, persistenza.

## Cosa non è ancora incluso (dopo 0.4)

- Nessun tick temporale, nessuna nozione di tempo di Anthalys.
- Nessuna decisione degli NPC, nessuna azione, nessun effetto sui bisogni
  diverso dal decadimento.
- Nessuna relazione, nessun mood.

## Prossimo incremento (0.5)

Utility AI deterministica minima: dato un personaggio con i suoi bisogni
correnti e un catalogo chiuso di azioni disponibili per location, produrre
una scelta riproducibile con seed. Nessun tempo, nessun movimento: solo la
decisione.
